本页是**写作者视角**的操作手册：一天里真正会点到的按钮、会遇到的提示，以及每步背后的规则。部署、AI Key 配置与环境变量请看[快速开始](/docs/getting-started)与[AI 接入](/docs/ai-setup)；逐元素的内容模型与属性定义见 [DITA 1.3 规范速查](/docs/dita-spec)。

同一个帮助中心也内置在工作台里：点击右上角「帮助」，或在编辑器外按 <kbd>?</kbd>，即可在不离开当前主题的情况下检索操作步骤、DITA 速查与快捷键。

## 一条完整链路

```text
打开手册 → 检出 → 编辑（可视化 / 双栏 / 源码）→ 自查诊断 → 签入 → 发布
```

关键点：**在签入之前，你的所有改动都只存在于个人草稿叠加层**。共享分支的 Git 工作区始终停留在 `HEAD`，同事看不到你的半成品，DITA-OT 校验也不会被别人的草稿污染。

## 检出与只读

未被检出的主题以只读方式打开，底部提示「文件尚未检出」。点击「检出」获得 `(项目, 分支, 文件)` 维度的独占锁：

- 同一时刻只有一个人能编辑同一个文件，其他人在同一分支看到的是只读视图。
- 锁与草稿生命周期解耦：草稿存在不会自动续期，闲置锁可以被释放后由他人重新检出。
- 检出只建立锁与草稿记录，**不修改任何 DITA 内容**，也不会推进分支。

## 三种编辑模式

| 模式 | 适用场景 | 保证 |
| --- | --- | --- |
| 可视化 | 日常写作、调整结构 | ProseMirror 原生 Schema，内联元素是节点而非 mark，不合并空元素、不重排嵌套 |
| 双栏对比 | 校对、确认源码与所见一致 | 两侧共享同一文档，滚动与选区互相跟随 |
| XML 源码 | 精确调整属性、注释、PI | CodeMirror 6，切回可视化前强制做良构校验 |

切到可视化之前会先执行 `checkXmlWellFormed()`。XML 不合法时**阻止切换**，并给出行、列、偏移与错误消息，而不是把半解析的文档塞进可视化编辑器。

无损往返是硬约束：XML 声明、DOCTYPE、注释、处理指令、CDATA、命名空间、属性顺序都会原样保留；改一个文本节点只会改动序列化结果中的那一行，Git diff 因此保持最小。

## 结构引导

有序内容模型集中在 `@dita/core` 的 `DITA_SEQUENCE_MODEL` 中，编辑器据此在光标处提示「可以插入什么」：

- `<conbody>`：先段落（`<p>` 等），后 `<section>` / `<example>`。
- `<taskbody>`：严格顺序 `prereq? → context? → steps|steps-unordered? → result? → tasktroubleshooting? → example? → postreq?`。
- 违反顺序只产生 `child-out-of-order` 诊断，**不会拦截输入**；未知与特化元素一律原样透传。

## 元素与表格

- 元素插入菜单（<kbd>⌘/Ctrl</kbd> + <kbd>/</kbd>）只列出当前上下文合法的子元素，并区分结构 / 块级 / 内联三组。
- CALS 表格按 `namest` / `nameend` / `morerows` 计算 `colspan` / `rowspan`，`<colspec>` 作为显式节点保留，因此表格内的注释与属性顺序都不会丢。
- 多 `<tgroup>` 表格禁止可视化拖拽，避免破坏结构；需要重构时改源码。

## 复用：conref 与 conkeyref

- `conref` 直接引用仓库中的片段，`conkeyref` 通过 key 间接引用（主题换库时只改 key 定义）。
- 插入前会检查目标是否存在；解析结果以只读投影呈现，修改必须回到源片段，否则下次解析就被覆盖。
- 引用目标上除 `id` 外的定位属性要谨慎：`conref` 只取被引用元素本身，多余的受众/条件属性容易让过滤结果与预期不符。

## 条件过滤（DITAVAL）

按 `audience` / `platform` / `product` / `props` 过滤投影，用于「同一份内容，多种交付物」。过滤只影响显示与发布，**不会删除 XML 中的任何条件属性**。

## 交叉引用、key 与 Map

- `<xref>` 指向主题或元素 `id`；跨手册引用先定义 key，再用 `keyref`，保证内容重组后链接不断。
- Map 结构在左侧导航中直接编辑，增删 `topicref` 等同于结构调整，签入时与主题改动一起提交。

## 大纲与导航

左侧大纲可按文本、标签或 `id` 过滤，支持拖拽重排与 <kbd>Alt</kbd> + <kbd>↑/↓</kbd> 移动当前块；非法落点会给出原因，但不阻止你继续编辑。

## 自查：三层校验

1. **实时约束**：编辑器对当前文档做内容模型检查，以装饰与底部问题面板呈现，不阻断输入。
2. **跨文件诊断**：语义索引检查 key、conref、xref 与 Map 引用，缺失目标定位到具体文件与行。
3. **严格校验**：签入前调用 DITA-OT 做 OASIS DTD 校验，默认在「我的草稿」临时物化上运行，只有通过才写入分支。

红色错误会阻止签入；警告可以带着签入，之后再修。

## 签入、合并与历史

- **签入**：对话框列出你改动的文件，把选中的草稿合成一个提交写回分支，并同步主题归属（`topic_assignments.topic_path`）。
- **合并**：他人已推入同一文件时进入三路合并，逐处选择保留版本；合并结束后共享工作区必须回到干净状态。
- **历史**：可查看提交差异、还原到某个版本或撤销某次提交。撤销以新提交表达，不重写历史。
- **放弃草稿**：丢弃未签入的改动，此操作不可恢复。

## 发布

- **HTML5**：静态主题（`dev-dark` / `editorial-paper` / `enterprise-manual` / `tech-docs`，以及不做后处理的 `vanilla`），由确定性 Node 后处理注入样式与离线搜索索引；产物可在 `file://` 下直接打开。
- **PDF**：四套主题（`compact-guide` / `editorial-book` / `enterprise-spec` / `tech-manual`），通过 `--customization.dir` 与 XML Catalog 注入页面尺寸、字体与页眉页脚属性层，中文字体默认使用 Noto CJK。
- **取用范围**：正式发布默认取干净基线（`HEAD` / Tag / Commit）；需要预览未签入效果时选择「我的草稿」，只包含你自己的草稿。
- **排错**：发布失败先看任务日志末尾。字体相关报错会附带修复提示（安装 `fonts-noto-cjk`、设置 `DITAEDITOR_NOTO_CJK_DIR`，或改为发布 HTML5）。

## 协作与版本模型

Git 干净基线 + 个人草稿叠加层：未签入的修改、新建、删除与图片资源都留在你的草稿里；只有签入、合并与回滚会推进共享分支的 `HEAD`。分支彼此隔离，各自使用独立的 `git worktree`，切换分支不会互相覆盖。

任务委派只写入 SQLite，不锁文件、不改 XML；对方检出后任务自动进入「进行中」。

## 常见问题

**为什么我的主题是只读的？** 有人持有锁，或你还没检出。查看文件树上的锁标记，必要时联系锁的持有者释放。

**为什么切不到可视化？** 源码存在良构错误。按提示的行列修好 XML，或使用「格式化 / 修复」再切换。

**为什么签入按钮不可用？** 存在红色错误，或没有选中任何草稿文件。

**别人的改动去哪了？** 分支隔离：切换分支后看到的是该分支的基线。用历史面板查看差异与提交记录。
