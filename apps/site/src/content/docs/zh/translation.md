DITAEditor 不把译文塞进私有翻译库，也不复制一份“翻译专用”的 XML。**每一种目标语言都是一本真实的手册**：有自己的目录、Git 仓库、分支、锁、草稿层与发布主题。翻译只是把源手册与目标手册按文件配成一对，然后在这个配对上做增量同步、AI 翻译、双语审校与签入。

这样做的好处是可验证的：译文随时能在普通编辑器里打开、校验、对比与发布；解除配对不会丢译文；某一种语言卡住，也不会把其他语言或源文锁死。

## 语言家族与配对关系

- 一本手册有一个**源语言**（`manuals.source_lang`，例如 `zh-CN`）。没有源语言的手册仍可编辑，只是不能作为翻译源。
- “添加目标语言”时可以**新建目标手册**（生成目录骨架、根 Map 与 Git 仓库），也可以**绑定已有手册**。
- 配对记录存在 SQLite 的 `translation_links`，包含源/目标手册、分支、语言与选项；文件级水位与状态存在 `translation_file_states`。
- 目标语言还可以继续作为下一级源语言，形成任意深度的**语言血缘**（例如 `zh-CN → en-US → ar-SA`）。上游未同步时，翻译中心会用非阻断提示标出风险，而不是禁止继续工作。
- 配对只建立映射，不复制 DITA 内容：目标文件在第一次审校签入时才真正写入目标分支。

## 从扫描到翻译：只处理真正变化的段落

在“文件”标签页点“扫描增量变更”，系统会：

1. 按相对路径对齐源/目标文件，识别新增、删除、重命名（`git diff -M`）。
2. 对每个 Topic 与 Map 运行 `git diff`，跳过只有属性、注释或格式变化的**仅元数据变更**。
3. 把当前源文 `S1`、上一版源文 `S0` 与既有译文 `T0` 做**三方段落对齐**，得到：
   - `unchanged`：直接复用 `T0`，不调用模型；
   - `modified` / `added`：只需要翻译这些段落；
   - `protected`：`codeblock`、`pre`、`lines`、`screen`、`msgblock`、`conref` 与 `translate="no"` 的内容原样搬运；
   - `deleted`：列出被删除的段落，供审校时确认。
4. 如果 `S0` 与 `T0` 的结构匹配率低于 50%，计划会退化为 `full_with_reference`：整篇重译，但把旧译文作为参考交给模型，避免错位拼接。

段落对齐依次尝试 `element_id`、结构路径、内容哈希与标签 LCS。`navtitle` 与 Map 根 `title` 属性也作为可翻译段落处理；`keydef` Map 会被标记为“需人工复核”，因为键定义往往决定全局文案。

图片与资源不走 AI：SVG 与位图可以直接复用源文件；如果图里含界面文字，审校时在目标编辑器替换为本地化版本，之后的源图更新不会覆盖你的本地版本。

## AI 翻译队列

翻译任务是 SQLite 中的 `translation_jobs` 与 `translation_items`，由进程内 worker 执行，不依赖 Redis、RabbitMQ 或外部任务系统。

- 按配对（`translation_links`）维护任务列表，SSE 推送进度；页面刷新不会丢任务。
- 每个文件先在临时目录生成译文，再做确定性 QA；失败项可以重试，任务可以取消。
- 每个配对可单独设置：复用未变更段落、严格 QA 门槛、独立 AI 审校、DITA-OT 严格校验、目标地区风格。这些设置只影响翻译流程，不改任何 DITA 文档。
- 队列里能看到复用段落数、新译段落数、QA 错误/警告、AI 审校结论与 DITA-OT 校验结果。

模型配置与普通 AI 助手共用一套服务端设置，详见 [AI 接入与安全边界](/docs/ai-setup)。不配置模型也可以使用：目标手册就是普通手册，手工翻译或在外部工具里翻译后放回草稿都可以。

## 双语审校

AI 译文不会直接写进目标基线，而是先成为**待审校提案**。打开“双语审校”后：

- 四种视图：**左右对照**、**双语交错**、**沉浸对照**、**XML 差异**；可以只看有变更或 QA 问题的段落。
- 每个段落都能直接编辑：富文本模式保留 DITA 行内标签，切到 XML 模式可以精确修改属性与标签；属性段落按纯文本编辑。
- **行内标签守恒**：译文缺少源文的 `<b>`、`<xref>`、`<codeph>` 等标签时，会列出缺失标签并允许一键补插；`id`、`href`、`keyref`、`conref`、`conkeyref`、`scope`、`format` 等属性必须与源文一致。
- **实时 QA**：命中术语、禁用译法、DNT、占位符（`{0}`、`{{name}}`、`%s`、`${name}`）与良构问题即时提示；每个段落可以只对这段发起“AI 优化”。
- **独立 AI 审校**：可指定单独的审校模型逐段复核，未通过时自动修复并重跑，报告按准确性、漏译、术语、标签、文体与 QA 违规分类。
- **DITA-OT 严格校验**：整批完成后在临时目录运行严格校验并自动修复可修复的错误，不会触碰共享工作区。

审校完成后点“应用到目标草稿”：译文写入目标手册的 `working_drafts`，仍然只有你自己的草稿可见。确认无误再“签入基线”，这一步才推进目标分支的 Git `HEAD`。目标文件被他人锁定时，应用会被拒绝并提示锁的持有者。

## 术语库

术语库分**全局**与**手册级**，按源语言匹配，在 AI 翻译与实时 QA 中自动合并生效。

- 每条术语支持同义词、大小写敏感、词性、上下文备注、状态（已批准/草稿/已弃用）、多个目标语言的译法与**禁用译法**。
- 标记为 **DNT（不翻译）** 的术语必须原样保留；使用禁用译法会产生 QA 错误。
- 支持 CSV、JSON 与 TBX-Basic 导入导出；导入先“预检”，逐行报告新增、更新与无效行，确认后才写库。

## 签入与发布

- 目标语言有自己的分支与 Check-out 锁；翻译签入与普通写作签入走同一套“干净基线 + 个人草稿”规则。
- 每种语言可以独立选择 HTML5 / PDF 主题、品牌色与 logo；阿拉伯语等 RTL 内容由浏览器与 DITA-OT 的 `dir` 属性处理。
- 源文再次变更时，已同步文件会回到“待更新”，只重译变化段落；已经签入的译文不会因为一次扫描被覆盖。
- 解除配对只删除映射，目标手册与已有译文保留，可稍后重新绑定。

## 明确的边界

- 不是实时协同翻译：没有 CRDT，也不做多人同时改同一段；协作仍由 Check-out 锁与草稿层保证。
- 不是完整的 TMS：不做报价、供应商门户、翻译记忆库计费或工期管理；段落复用是确定性的增量机制，不是跨项目翻译记忆。
- AI 是可选的：不配模型也能建配对、扫描、手工编辑、QA、审校与签入。
- 目标基线只通过签入推进；扫描、翻译、审校都不会悄悄改动共享工作区。
